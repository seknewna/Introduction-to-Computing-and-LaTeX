Case Statements, Arrays & Substitution

Case statements offer a cleaner alternative to long if/elif chains. This chapter also introduces indexed and associative arrays, the IFS variable that controls word-splitting, command substitution, arithmetic expressions, and process substitution.

View script
bash-scripting/scripts/04-case-arrays-substitution.sh 
#!/usr/bin/env bash
#
# Chapter 04 — Case Statements, Arrays & Substitution
# Real commands: case/esac, indexed & associative arrays, IFS,
# $(...) command substitution, $((...)) arithmetic, <(...) process sub.

for name in dave bill anyone; do
    case "$name" in
        d*)  echo "matched d*: $name" ;;
        b*)  echo "matched b*: $name" ;;
        *)   echo "matched *: $name"  ;;
    esac
done

echo
echo "Indexed array — note *the difference* between [*] and [@]:"
array=(foo bar baz)
echo "element 0: ${array[0]}"
echo "last element: ${array[-1]}"
echo "all (as one word): ${array[*]}"
echo "all (as separate words): ${array[@]}"

echo
echo "Associative array — string keys instead of positions:"
declare -A capitals=([France]=Paris [Japan]=Tokyo)
for key in "${!capitals[@]}"; do
    echo "$key is ${capitals[$key]}"
done

echo
echo "Command substitution — prefer \$(...) over legacy backticks:"
thing=$(whoami)
echo "thing is $thing"

echo
echo "Arithmetic expression:"
i=0
((i++))
echo "i is $i"
echo "2 + 2 = $((2 + 2))"

echo
echo "Process substitution treats a command's output like a file:"
diff <(printf 'a\nb\n') <(printf 'a\nc\n') || true

Sourcing Code, Subshells & Return vs. Output

Sourcing loads another file's code into your current shell, while curly braces { } and parentheses ( ) control whether commands run in your current shell or an isolated subshell. Also covers the difference between a function's numeric return status and its printed output.

View script
bash-scripting/scripts/07-sourcing-and-subshells.sh 
#!/usr/bin/env bash
#
# Chapter 07 — Sourcing Code, Subshells & Return vs. Output
# Real commands: source, { } vs ( ), capturing stdout vs stderr
# separately when calling a function.

cat > lib.sh << 'INNER_EOF'
greet() {
    local name=$1
    echo "hello $name!"
}
INNER_EOF

source lib.sh      # loads greet() into THIS shell
greet dave
rm lib.sh

echo
echo "{ } runs in the current shell; ( ) runs in an isolated subshell:"
{ set_in_brace="yes"; }
echo "set_in_brace=$set_in_brace"
( set_in_paren="yes" )
echo "set_in_paren='${set_in_paren:-unset}'"

echo
echo "A function's stdout and stderr can be redirected independently:"
my-func() {
    echo "this goes to stdout" >&1
    echo "this goes to stderr" >&2
}
output=$(my-func 2>/dev/null)   # keep stdout, throw away stderr
echo "captured: $output"

Parameter & Array Expansion

Bash's parameter expansion syntax packs a lot of power into a small space: default values for unset variables, trimming prefixes and suffixes off strings, search-and-replace, and slicing arrays by index.

View script
bash-scripting/scripts/08-parameter-and-array-expansion.sh 
#!/usr/bin/env bash
#
# Chapter 08 — Parameter & Array Expansion
# Real commands: case conversion (^ , ,), default/required values
# (:-  ?), replacements (# ## % // ), substrings, array slicing.

s='dave eddy'
echo "uppercase first letter: ${s^}"
echo "uppercase everything:   ${s^^}"

echo
name=${1:-dave}
echo "default if unset: $name"

path=/home/dave/data.txt
echo "strip shortest prefix:  ${path#*/}"
echo "strip longest prefix:   ${path##*/}"
echo "strip shortest suffix:  ${path%/*}"
echo "replace first match:    ${path/a/o}"
echo "replace all matches:    ${path//a/o}"

echo
echo "Substrings by offset and length:"
echo "${s:0:4}"
echo "${s: -4}"

echo
echo "Loop a string one character at a time using substring expansion:"
len=${#s}
for ((i = 0; i < len; i++)); do
    printf '%s' "${s:i:1}"
done
echo

echo
echo "Array expansion works the same way, applied to every element:"
arr=(foo bar baz)
printf '<%s>\n' "${arr[@]/a/1}"

Globbing

Wildcards like * and ? let you match filenames without listing them one by one. This chapter adds extended globbing for more expressive patterns and shell options like nullglob that change how a non-matching glob behaves.

View script
bash-scripting/scripts/09-globbing.sh 
#!/usr/bin/env bash
#
# Chapter 09 — Globbing
# Real commands: *, ?, [..] character classes, extglob's !( ) +( ) @( ),
# and the nullglob/dotglob/globstar shell options.

mkdir -p files
touch files/foo.txt files/foo.jpg files/bar.txt files/baz.jpg

echo "Basic wildcard — every .txt file:"
printf '%s\n' files/*.txt

echo
echo "? matches exactly one character:"
printf '%s\n' files/ba?.txt

echo
echo "[..] matches one character from a set:"
printf '%s\n' files/ba[rz].txt

echo

shopt -s nullglob
printf '<%s>\n' files/*.md

# Chapter 11 — printf, Date Formatting & Regular Expressions

Trap Signals & Named Pipes

trap intercepts signals like Ctrl+C so your script can clean up before exiting, and named pipes (FIFOs) let two separate processes pass data through a file-like path on disk.

View script

#
# Chapter 13 — Trap Signals & Named Pipes
# Real commands: trap ... exit, mkfifo, reading/writing a FIFO path.

cleanup() {
    echo "cleanup function running"
}
trap cleanup exit

echo "script starting"
echo "..."
echo "script done"
# 'cleanup' fires here automatically because of the trap on exit

Common Pitfalls

Field notes from real bugs: why parsing 'ls' output breaks on odd filenames, why aliases can't take arguments the way functions can, and why string length can surprise you with multibyte characters.

View script

#!/usr/bin/env bash
#
# Chapter 16 — Common Pitfalls
# Real commands: the classic `for f in $(ls)` bug, alias argument
# limitations, and ANSI codes inflating string length.

mkdir -p files
touch files/a files/b "files/d      e"

echo "The fragile way — breaks on filenames containing spaces:"
for f in $(ls files); do
    echo "  bad: $f"
done

echo
echo "The safe way — glob directly, no ls, no word-splitting:"
for f in files/*; do
    echo "  good: $f"
done

rm -rf files

echo
echo "Aliases can't take positional arguments the way functions can:"
shopt -s expand_aliases
alias greet-alias='echo hello \$1'   # \$1 never gets replaced
greet-alias world

greet-func() { echo "hello $1"; }
greet-func world

echo

echo "invisible on screen:"
colored=$'\e[33mHello\e[0m'
echo "visible text is 5 characters, but \${#colored} reports: ${#colored}"

## What is R?

R is a statistical programming language created in 1992 by Ross Ihaka and
Robert Gentleman at the University of Auckland, New Zealand, and first
released as version 1.0 in February 2000. Its name comes from the initials
of its creators' first names. R descends from the S language, which was
developed at Bell Laboratories in the mid-1970s. See the
[official R project page](https://www.r-project.org/about.html) for more
history.

## Value Matching

`match()` returns the position of the first match of its first argument in
its second argument. Check `?match` for the full documentation.
```{r}
match("Species", c("Sepal.Length", "Sepal.Width", "Petal.Length",
                    "Petal.Width", "Species"))
```

`%in%` checks whether a value exists anywhere in a vector, returning
`TRUE`/`FALSE` instead of a position:
```{r}
"Species" %in% c("Sepal.Length", "Sepal.Width", "Petal.Length",
                  "Petal.Width", "Species")
```

# Assignment

R accepts three assignment operators: `<-`, `=`, and `->`.

A variable name:

* can begin with a letter or a dot. E.g. `a <- 1`, `0 -> .a`
* cannot contain spaces — use `_` or `.` instead
* can contain numbers, just not as the first character. E.g. `a1 <- 1`

```{r error=TRUE}
v rsion <- 4.3.2 # invalid: a space inside the name breaks the parser
```

```{r}
a <- 1
b <- 2
0 -> .a
a1 <- .a
```

## Eigenvalues / eigenvectors

Eigenvalues $\lambda$ of a square matrix $A$ solve the characteristic
equation $\det(A - \lambda I_n) = 0$. They're the mathematical basis of
[Principal Component Analysis](https://www.datacamp.com/tutorial/pca-analysis-r),
covered in Chapter 15.

```{r}
ev <- eigen(A)
print(ev$values)

P <- ev$vectors
round(solve(P) %*% A %*% P, 4) # recovers a diagonal matrix of eigenvalues
```

## Worked exercise: manual PCA on `iris`

1. Remove the last column (`Species`) from `iris`:
```{r}
data(iris)
dta <- iris[, -5]
```

2. Compute the average of each remaining column:
```{r}
avg <- colMeans(dta)
print(avg)
```

3. Center the data by subtracting each column's average:
```{r}
scaled_dta <- scale(dta, center = TRUE, scale = FALSE)
head(scaled_dta, 3)
```

4. Eigen-decompose `t(scaled_dta) %*% scaled_dta`:
```{r}
cov_mat <- t(scaled_dta) %*% scaled_dta
ev <- eigen(cov_mat)
ev$values
```

5. Project onto the first two eigenvectors:
```{r}
P <- ev$vectors[, 1:2]
projection <- scaled_dta %*% P
head(projection)
```

This is exactly what `prcomp()` does under the hood:
```{r}
pca <- prcomp(dta, center = TRUE, scale. = FALSE)
head(pca$x[, 1:2])
```

# Outlier Detection

## The Inter-Quartile Range (IQR) method

A value outside the interval below is treated as an outlier:

$$[Q_1 - 1.5\times IQR,\ Q_3 + 1.5\times IQR]$$

where $Q_1$/$Q_3$ are the 25th/75th percentiles and $IQR = Q_3 - Q_1$.

```{r fig.height=4, fig.width=5}
x <- c(19.103, 19.632, 22.494, 20.113, 10.5, 22.744, 20.737, 17.976,
       18.901, 192.87, 21.959, 0.001, 20.641, 20.177, 19.111, 22.859,
       207.97, 16.853, 21.122, 19.244, 18.291, 19.651, 18.358, 18.834, 19)

x_copy <- x
boxplot(x_copy, main = "Before handling outliers")
```

```{r}
Q <- as.numeric(quantile(x, probs = c(0.25, 0.5, 0.75)))
d <- as.data.frame(t(Q))
names(d) <- paste0("Q", 1:length(Q))
d$IQR      <- d$Q3 - d$Q1
d$LowerLim <- d$Q1 - 1.5 * d$IQR
d$UpperLim <- d$Q3 + 1.5 * d$IQR
d
```

Flagging every value as an outlier or not:
```{r}
(d_out <- data.frame(x = x, outlier = x < d$LowerLim | x > d$UpperLim))
```

Two equivalent ways to pull out just the outliers:
```{r}
x[d_out$outlier]                                  # using our own table
(bxpt <- boxplot(x, range = 1.5, plot = FALSE))$out # using boxplot()'s own $out
```

## Imputing the outliers

Treat outliers as missing, then fill them with the mean of everything else:
```{r}
x[d_out$outlier] <- NA
x[is.na(x)] <- mean(x, na.rm = TRUE)
```

```{r fig.height=4, fig.width=7}
par(mfrow = c(1, 2))
boxplot(x_copy, main = "Before\nhandling outliers", cex.main = 0.8)
boxplot(x, main = "After\nhandling outliers", col = "green", cex.main = 0.8)
```

No more outliers remain after imputation.

## 2. Solve a quadratic equation and comment on its discriminant

For $ax^2 + bx + c = 0$:

```
                  ┌─ discriminant > 0 → two distinct real roots
compute disc = b² - 4ac ─┤─ discriminant = 0 → one repeated real root
                  └─ discriminant < 0 → two complex conjugate roots
```

```{r}
solve_quadratic <- function(a, b, c) {
  if (a == 0) stop("a must be non-zero for a quadratic equation")

  disc <- b^2 - 4 * a * c

  if (disc > 0) {
    message("Two distinct real roots")
    roots <- c((-b + sqrt(disc)) / (2 * a), (-b - sqrt(disc)) / (2 * a))
  } else if (disc == 0) {
    message("One repeated real root")
    roots <- -b / (2 * a)
  } else {
    message("Two complex conjugate roots")
    real_part <- -b / (2 * a)
    imag_part <- sqrt(-disc) / (2 * a)
    roots <- c(complex(real = real_part, imaginary = imag_part),
               complex(real = real_part, imaginary = -imag_part))
  }
  roots
}

solve_quadratic(1, -3, 2)  # disc > 0
solve_quadratic(1, 2, 1)   # disc == 0
solve_quadratic(1, 0, 1)   # disc < 0
```

# The Pipe

Two pipe operators are common in R:

* `%>%` from the `magrittr` package (loaded with `tidyverse`/`dplyr`)
* `|>` the base-R native pipe

A regular expression (regex) is a pattern used to match, extract, or
replace text. R's base functions for this all take a pattern as their
first serious argument and a character vector to search as the second.

```{r}
text <- c("dave@example.com", "call 555-1234", "no match here", "ID: R2024-001")
```

# Detecting Matches

`grepl()` returns `TRUE`/`FALSE` for each element:
```{r}
grepl("[0-9]+", text)
```

`grep()` returns matching positions, or the matching strings themselves
with `value = TRUE`:
```{r}
grep("[0-9]+", text)
grep("[0-9]+", text, value = TRUE)
```

# Replacing Matches

`sub()` replaces only the first match per string; `gsub()` replaces all:
```{r}
sub("[0-9]+", "#", text)
gsub("[0-9]+", "#", text)
```

# Extracting Matches

`regexpr()` finds the *first* match's position; `regmatches()` pulls out
the actual matched text:
```{r}
m <- regexpr("[0-9]+", text)
regmatches(text, m)
```

`gregexpr()` + `regmatches()` extracts *every* match per string:
```{r}
mg <- gregexpr("[0-9]+", text)
regmatches(text, mg)
```

# A Practical Pattern: Validating an Email

```{r}
grepl("^[A-Za-z]+@[A-Za-z]+\\.[a-z]+$", text)
```

# Common Building Blocks

| Pattern | Matches |
|---|---|
| `[0-9]` or `\\d` | any digit |
| `[a-zA-Z]` | any letter |
| `.` | any single character |
| `+` | one or more of the previous token |
| `*` | zero or more of the previous token |
| `^` / `$` | start / end of the string |
| `\\s` | whitespace |
| `\|` | alternation ("or") |

# `stringr` Equivalents

The `stringr` package (part of `tidyverse`) wraps the same regex engine in
more consistent, pipe-friendly functions:
```{r message=FALSE}
library(stringr)
str_detect(text, "[0-9]+")
str_extract(text, "[0-9]+")
str_extract_all(text, "[0-9]+")
str_replace_all(text, "[0-9]+", "#")
```

Concepts

What Is LaTeX?

Most word processors are WYSIWYG — what you see is what you get. You click, drag, and format a page directly, and the tool shows you the result as you go.

LaTeX works the opposite way. You write a plain text file full of commands that describe what things are — a section, a table, an equation — not how they should look pixel-by-pixel. A program called a TeX engine then reads that file and compiles it into a finished PDF.

The upshot: you focus on content and structure, and LaTeX handles the visual formatting for you, consistently, every time.

Concepts

Why Learn LaTeX?

  • Handles complex math, technical notation, and large tables far more gracefully than a word processor.
  • Numbers figures, equations, citations, and table-of-contents entries automatically — renumber freely without breaking anything.
  • Separates content from style: rewrite what a document looks like without touching a word of what it says.
  • Extensible through thousands of free, community-written packages.

It's not the right tool for everything — free-form magazine-style layouts are still easier in a visual design tool. But for anything technical, academic, or reference-heavy, it earns its learning curve fast.
